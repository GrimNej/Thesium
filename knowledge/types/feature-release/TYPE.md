# Feature Release — Video Type

> The "what's new" film: one new feature, or a short changelog, shown so clearly that existing
> users try it today. Grammar benchmarks (copy nothing): Linear changelog videos, Figma and
> Notion release clips, Raycast feature drops, GitHub Universe announcements.

## 1. The job, and what it is not

- **Job:** announce one capability and make its value instant. Success: adoption of the feature,
  shares from existing users, visits to the changelog.
- **Audience:** people who already use the product; skip the company introduction.
- **Not** a full product launch and not a tutorial: one idea, shown, celebrated, done.

## 2. Beat structure

| Length | Beats (seconds) |
|---|---|
| 10–15 s | "New" tag + feature name 0–2 · the feature doing its thing 2–10 · where to find it + CTA 10–15 |
| 30 s | The old friction 0–4 · "Introducing <feature>" 4–7 · demo in two moves 7–20 · one detail users will love 20–25 · availability (plan, date, platform) + CTA 25–30 |
| Changelog, 30–45 s | Release name 0–3 · 3–5 items, one card each (5–7 s) · "and more" montage · version and CTA |

## 3. Must-haves

- A "New" or version tag in the product's own badge style.
- The feature in the real interface, zoomed so its result is readable.
- Exact availability from the sources (plans, platforms, rollout date).
- Before and after when the value is a saving of time, clicks or steps; show the number only if
  the sources give it.

## 4. Motion and visual language

- **Snappy and precise**: quick masked reveals, keyboard shortcuts as keycaps that press down,
  command palettes typing themselves, results springing in.
- **Spotlight on the new**: the rest of the UI dims or blurs; the new control glows, scales and
  gets a moving highlight ring; then the UI settles back around it.
- **Proof in motion**: counters ticking, timers racing, the slow way replaced by the instant one
  in a side-by-side wipe.
- Signature options: the feature name typed into the product's own command bar; a release-note
  card unfolding into the live feature; a version number rolling like an odometer.

## 5. Type and copy

Feature name verbatim from the sources, in display weight; one benefit line; keycaps for
shortcuts in a mono font. Keep the product's voice, playful or austere as the brand is.

## 6. Sound

Short and crisp: a confident beat around 120 BPM, keycap clicks, a sparkle on the reveal, a clean
button sound on the CTA. Works muted.

## 7. Formats and delivery

16:9 for blogs and changelog pages; 1:1 and 9:16 cuts for social, framed on the zoomed UI.

## 8. What to take from the sources

Feature name, release or version number, what it replaces, availability, screenshots or page video
of the feature, keyboard shortcuts, any measured improvement.

## 9. Pitfalls

- Re-introducing the whole company before the feature.
- Showing the feature too small to read.
- Claiming improvements the sources do not state.

## 10. Variation space

- Openings: the frustrating old way at speed; shortcut keys pressed in macro; a user request from
  the sources, answered.
- Structures: one feature, three uses; a changelog as a stack of cards; the feature solving a tiny
  story.
- Endings: the "New" badge stamping onto the product; the version number settling; a CTA to the
  changelog.

## 11. Pairs well with

Living Screencast, Dark Tech Keynote, ASCII / CRT Terminal (developer tools), Swiss Motion
Graphics.
